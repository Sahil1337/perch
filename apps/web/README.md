# @perch/web

The [Perch](../../README.md) UI: a React SPA that talks to `perch serve` over HTTP, and that ships
*inside* the server binary rather than beside it.

This workspace is deliberately thin. **Components live in [`@perch/ui`](../../packages/ui)**; what
is here is the app shape — the router, the shell, and the wiring that turns the HTTP API into the
workspace contract those components consume.

## How it ships

TanStack Start in **SPA mode**. Start's server half never runs: there is no SSR and there are no
server functions, only a shell that gets prerendered once at build time.

```
vite build            →  dist/client/            the static bundle, index.html at its root
scripts/postbuild.mjs →  apps/server/ui/         copied wholesale
scripts/build.sh      →  apps/server/webui/static/  staged for //go:embed
go build              →  one binary that serves the UI at /
```

Both of those directories are build output and gitignored. The `index.html` at the root of the
build is load-bearing: `apps/server/server/ui.go` returns that exact file for every unmatched
non-`/api/` GET, which is what makes client-side routing work off a plain static mount.

That is also why `bun run build` at the repo root is ordered rather than fanned out — `@perch/web`
first, then `perch`.

## Running it

Always from the repo root; there is one lockfile and one `node_modules` for the whole repo.

```sh
bun run dev                        # both halves: this UI on :5173, the API on a free port
bun run dev:ui                     # just the UI, expecting an API on :4600
bun run --filter @perch/web build  # vite build + the copy into apps/server/ui/
```

In development the UI and the API are on **different origins**, so the browser only reaches the
API because the server allow-lists the UI's origin for CORS. That list is fixed, which is why
Vite's port is pinned with `strictPort: true` — a UI that walked to :5174 because :5173 was busy
would fail in the browser, with nothing in the terminal to explain it. Stop any dev UI you already
have running instead.

`VITE_PERCH_URL` tells the UI where the API is. `bun run dev` sets it per run (the port is picked
fresh each time); `bun run dev:ui` falls back to `.env.development`, which agrees with the :4600
that `dev:server` defaults to. In a build it is deliberately unset: the bundle is served by the
same process as the API, so the origin is the page's own.

## Layout

```
src/
  routes/
    __root.tsx        the document shell — head, theme boot script, fonts
    index.tsx         the workspace: sidebar, editor grid, results sheet, palette
  lib/
    app-workspace.tsx the one place that names which provider the app runs on
    live-workspace/   that provider: WorkspaceApi implemented against the HTTP API
    server-client.ts  the only module in the app that constructs a @perch/client
    use-panels.ts     pane geometry, in localStorage — per-machine appearance state
  run-history.tsx     the history panel, grouped by day
  styles.css          Tailwind entry, fonts, and the import of @perch/ui's design system
  routeTree.gen.ts    generated by the router plugin. Committed, never hand-edited.
```

## Live data

`src/lib/live-workspace/` implements the `WorkspaceApi` contract that every `@perch/ui` surface
takes, one hook per concern: connections, databases, schema, buffers, file sessions, runs,
settings, server events, and the gate that covers all of them while the server is unreachable.

**There is no fixture mode.** A SQL client that quietly shows invented tables is worse than one
that says it cannot reach its server, so every row on screen came off the wire and failures render
as failures (`<ServerGate>`). `app-workspace.tsx` stays as the single seam that names the provider,
so no surface imports it directly.

`server-client.ts` builds the `@perch/client` lazily and memoises it, so the SSE stream and every
request agree on one base URL.

## Rules that bite

- **Never install inside this workspace.** Add the dependency to `package.json` and run
  `bun install` at the repo root — a nested lockfile means a second copy of React.
- **Components belong in `@perch/ui`** unless they are app-shaped (routing, providers, wiring).
  Nothing in `packages/ui` may import `@perch/client`; `src/lib` is the only place that does.
- **Tailwind first, and the linter enforces it.** Hand-rolled CSS, raw colors and arbitrary
  Tailwind values fail `bun run lint`. Use theme tokens and real utilities; plain CSS is for what
  Tailwind cannot express, like keyframes.
- **Don't edit `src/routeTree.gen.ts`.** The router plugin rewrites it on every `vite dev` and
  `vite build`. It is committed so `typecheck` works from a clean checkout; if it turns up dirty,
  commit it with your work rather than reverting it.

The reasoning behind the workspace boundaries is in
[`docs/architecture/monorepo.md`](../../docs/architecture/monorepo.md); the component and state
conventions are in [`AGENTS.md`](../../AGENTS.md).
